## Структура тестирования по категориям

### 1. Unit тесты (встроенные в модули)
Каждый модуль содержит собственные unit тесты в блоках `#[cfg(test)]`:
- Тестируют отдельные функции и методы
- Используют моки для внешних зависимостей
- Быстрые и независимые от файловой системы

### 2. Интеграционные тесты

#### real_data_tests.rs (709 строк)
- Тесты с реальными медиафайлами
- Автоматически пропускаются в CI/CD окружении
- Покрывают сложные сценарии с различными кодеками

**Основные тестовые сценарии:**
- `test_extract_metadata_from_hevc_video` - HEVC видео 4K
- `test_extract_metadata_from_long_audio` - Длинные аудиофайлы (31 мин)
- `test_video_without_audio` - Видео без аудио дорожки
- `test_thumbnail_generation_4k_video` - Превью для 4K
- `test_handle_cyrillic_filename` - Файлы с кириллицей
- `test_parallel_processing` - Параллельная обработка
- `test_memory_usage_large_files` - Управление памятью

#### processor_test.rs (397 строк)
- Специализированные тесты процессора медиафайлов
- Тестирование пайплайнов обработки
- Проверка производительности и стабильности

### 3. Тестовые данные и моки

#### test_data.rs (366 строк)
- Константы для тестовых медиафайлов
- Структуры данных для мокирования
- Вспомогательные функции для генерации тестовых данных

**Тестовые файлы:**
- **C0666.MP4**, **C0783.MP4** - 4K HEVC, 50fps, PCM аудио (200 Mbps)
- **Kate.mp4** - 4K H.264, AAC аудио, 44.1kHz
- **water play3.mp4** - Видео без аудио, HEVC
- **проводка после лобби.mp4** - Кириллица в названии
- **DJI_02_20250402_104352.WAV** - Длинный аудиофайл (31 мин, 256 MB)
- **DSC07845.png** - Высокое разрешение (4240x2832)

#### test_ffmpeg_mock.rs (29 строк)
- Моки для FFmpeg команд
- Эмуляция ответов FFprobe
- Изоляция тестов от внешних зависимостей

### 4. Метаданные тесты

#### metadata/tests.rs
- Тесты парсинга метаданных
- Проверка обработки различных форматов
- Валидация данных из FFprobe

## Стратегия выполнения тестов

### Локальные тесты
- Все unit тесты выполняются всегда
- Интеграционные тесты с реальными файлами выполняются только локально
- Используется макрос `skip_in_ci!()` для пропуска в CI/CD

### CI/CD тесты
- Выполняются только unit тесты и тесты с моками
- Интеграционные тесты автоматически пропускаются
- Проверка через переменные окружения `CI` и `GITHUB_ACTIONS`

## Edge Cases и специальные сценарии

### Обрабатываемые сложности:
1. **Высокий битрейт**: Файлы 200+ Mbps
2. **PCM аудио в MP4**: Нестандартная комбинация
3. **Различные fps**: 50fps видео
4. **Смешанный контент**: Видео с аудио и без
5. **Большие файлы**: 250+ MB без блокировки UI
6. **Unicode имена**: Файлы с кириллицей и пробелами
7. **Множественные кодеки**: HEVC, H.264, различные аудио форматы

## Запуск тестов

```bash
# Все unit тесты
cargo test --package timeline-studio --lib media

# Только быстрые тесты (без интеграционных)
cargo test --package timeline-studio --lib media -- --skip real_data

# Интеграционные тесты (только локально)
cargo test --package timeline-studio --lib media::real_data_tests

# Тесты с выводом производительности
cargo test --package timeline-studio --lib media -- --nocapture
```
