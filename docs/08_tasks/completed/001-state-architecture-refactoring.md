# Задача: Рефакторинг архитектуры управления состоянием

## 📋 Описание

Текущая архитектура Timeline Studio имеет проблемы с дублированием состояния между различными XState машинами и отсутствием синхронизации между frontend и backend. Необходимо создать единую архитектуру управления состоянием с backend как единственным источником истины.

## 🎯 Цели

1. Устранить дублирование данных между машинами состояний
2. Реализовать автоматическую синхронизацию frontend и backend
3. Упростить управление состоянием проекта
4. Создать единый формат данных проекта
5. Реализовать Event Sourcing для истории изменений

## 🔍 Текущие проблемы

### Дублирование данных
- **Информация о проекте** хранится в 3 местах:
  - `app-settings-machine`: currentProject (path, name, isDirty)
  - `timeline-machine`: полный TimelineProject
  - `project-settings-machine`: ProjectSettings

- **Медиафайлы** дублируются в:
  - `app-settings-machine`: mediaFiles и musicFiles
  - `timeline-machine`: project.resources.media
  - `resources-machine`: mediaResources

- **Состояние воспроизведения**:
  - `player-machine`: управляет воспроизведением
  - `timeline-machine`: дублирует isPlaying, currentTime

### Отсутствие синхронизации
- Машины не знают об изменениях друг друга
- Нет единого канала для обновлений
- Frontend является источником истины, backend только сохраняет

### Сложность конвертации
- TimelineProject ↔ TimelineStudioProject требует сложной конвертации
- Разные форматы для сохранения (.tls vs .tlsp)

## 🏗️ Предлагаемая архитектура

### Event-Driven + Single Source of Truth

```
┌─────────────────────────────────────────────────────────────┐
│                    BACKEND (Rust/Tauri)                     │
├─────────────────────────────────────────────────────────────┤
│  ProjectState (Single Source of Truth)                      │
│  - Полное состояние проекта в памяти                      │
│  - Event Store для всех изменений                         │
│  - Автоматическая персистенция                            │
│                                                            │
│  EventBus                                                  │
│  - Broadcast изменений всем подписчикам                   │
│  - Command/Query разделение                               │
└─────────────────────────────────────────────────────────────┘
                              ↑ ↓
                    Tauri Events + Commands
                              ↑ ↓
┌─────────────────────────────────────────────────────────────┐
│                    FRONTEND (React)                         │
├─────────────────────────────────────────────────────────────┤
│  AppMachine (Orchestrator)                                 │
│  - Координирует все дочерние машины                       │
│  - Подписка на backend события                            │
│  - Отправка команд в backend                              │
│                                                            │
│  ├── TimelineMachine (View)                               │
│  │   - Только UI состояние                                │
│  │   - Отправляет команды в AppMachine                    │
│  │                                                         │
│  ├── PlayerMachine (View)                                  │
│  │   - Локальное состояние воспроизведения               │
│  │   - Синхронизация через AppMachine                     │
│  │                                                         │
│  └── ResourcesMachine (Cache)                              │
│      - Кэш ресурсов для быстрого доступа                 │
│      - Инвалидация при изменениях                        │
└─────────────────────────────────────────────────────────────┘
```

## 📊 Метрики успеха

1. **Производительность**
   - Задержка синхронизации < 16ms (60fps)
   - Время сохранения проекта < 100ms
   - Memory footprint снижен на 30%

2. **Надежность**
   - 0 потерь данных при сбоях
   - Автоматическое восстановление состояния
   - Корректная работа в оффлайн

3. **Код**
   - Удалено 50% дублирующего кода
   - Единый источник истины
   - Простота добавления новых features

## 🚀 Преимущества новой архитектуры

1. **Консистентность** - данные всегда синхронизированы
2. **Масштабируемость** - легко добавлять новые features
3. **История изменений** - полный Event Sourcing
4. **Оффлайн работа** - команды в очереди
