# Прямые трансляции с упрощённым интерфейсом

## Описание задачи

Реализовать функционал прямых трансляций, вдохновлённый OBS Studio, но с радикально упрощённым и интуитивным интерфейсом. Основная идея - убрать сложность настройки и предоставить готовые решения для типовых сценариев стриминга.

## Проблема с существующими решениями

OBS Studio - мощный инструмент, но:
- Сложный интерфейс для новичков
- Требует долгой настройки сцен
- Нужно разбираться с источниками, фильтрами, настройками кодеков
- Сложно быстро переключаться между камерами
- Неудобно управлять фоновой музыкой

## Наше решение

### 1. Готовые многокамерные шаблоны

Вместо создания сцен с нуля - выбор из готовых шаблонов:

- **Подкаст (2 участника)** - split screen для двух камер
- **Интервью** - основной спикер крупно + гость в углу
- **Презентация** - экран + камера докладчика
- **Игровой стрим** - игра + камера + чат
- **Вебинар** - до 4 участников в сетке
- **Концерт** - переключение между несколькими камерами

### 2. Упрощённая работа с музыкой

- **Музыкальная библиотека** встроенная с бесплатными треками
- **Плейлисты** для фоновой музыки
- **Автоматическое приглушение** музыки при разговоре
- **Интеграция с музыкальными сервисами** (с учётом авторских прав)
- **Звуковые эффекты** на горячих клавишах

### 3. Быстрая настройка

При запуске трансляции:
1. Выбираем шаблон
2. Подключаем камеры (автоопределение)
3. Выбираем фоновую музыку (опционально)
4. Указываем платформу (YouTube/Twitch/etc)
5. Начинаем трансляцию

### 4. Интеграции с платформами

#### YouTube
- Авторизация через API
- Автоматическое создание трансляции
- Управление чатом прямо в интерфейсе
- Предпросмотр комментариев перед показом
- Статистика в реальном времени

#### Twitch
- Быстрое подключение
- Интеграция с чатом
- Алерты о донатах и подписках

#### Другие платформы
- Facebook Live
- Instagram Live (через виртуальную камеру)
- VK Live
- Возможность multistreaming

### 5. Умные функции

- **Автопереключение камер** по голосу (кто говорит - тот в кадре)
- **Виртуальные фоны** без green screen (AI-based)
- **Автоматические титры** с именами спикеров
- **Картинка в картинке** для реакций
- **Мгновенные повторы** для игровых стримов

### 6. Простое управление во время стрима

- **Stream Deck** в интерфейсе для быстрых действий
- **Горячие клавиши** для всего
- **Мобильное приложение** для удалённого управления
- **Предпросмотр** всех камер одновременно

## Технические детали

### Архитектура

#### Основной стек
- **WebRTC** для захвата камер с низкой задержкой
- **FFmpeg 6.0+** для кодирования и стриминга
- **Tauri v2** вместо Electron (меньше ресурсов)
- **React + XState** для интерфейса и управления состоянием
- **WebGPU/WebGL** для композитинга видео

#### Streaming Pipeline
```typescript
interface StreamingPipeline {
  // Источники видео
  sources: {
    webcams: MediaStream[]
    screens: DesktopCapture[]
    ndi?: NDISource[]
    virtualCam?: VirtualCamera
  }
  
  // Обработка
  processing: {
    resolution: '720p' | '1080p' | '4K'
    framerate: 30 | 60
    codec: 'h264' | 'h265' | 'av1'
    hardwareAcceleration: 'nvenc' | 'qsv' | 'vce' | 'software'
  }
  
  // Выходы
  outputs: {
    rtmp: RTMPOutput[]
    hls?: HLSOutput
    recording?: LocalRecording
  }
}
```

### Производительность

#### Оптимизации
- **GPU ускорение** через NVENC/QuickSync/VCE
- **Многопоточность** для обработки источников
- **Умное кеширование** композиций
- **Прокси-превью** для слабых компьютеров
- **Адаптивный битрейт** (ABR) по качеству сети

#### Целевые показатели
- CPU usage < 30% для 2 камер @ 1080p30
- RAM < 500MB базовое потребление
- Задержка < 100ms от камеры до превью
- Startup time < 3 секунды

## Риски и митигация

1. **Конкуренция с OBS**
   - Риск: Пользователи привыкли к OBS
   - Митигация: Фокус на простоте, не пытаться заменить OBS полностью

2. **Стабильность стрима**
   - Риск: Обрывы, лаги
   - Митигация: Надёжная архитектура, fallback механизмы

3. **Производительность**
   - Риск: Высокая нагрузка на систему
   - Митигация: GPU ускорение, оптимизация
